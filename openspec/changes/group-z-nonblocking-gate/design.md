# Design: group-z-nonblocking-gate

## Context

`RoadmapReader.getActionablePhaseNumbers` is the single source of "which phases are open" for the orchestrator: `run.js` uses it to compute the unblocked pending set that gates idle continuation, and `action-resolver.js` uses it to list HUMAN items. It currently requires every item of every dependency phase to be complete or parked. Roadmaps generated by Riley end each phase with `### Group Z: User Testing` holding a `[HUMAN]` checkpoint, and Morgan is instructed that these checkpoints never block the next phase.

## Goals / Non-Goals

**Goals:** make the reader's gate agree with Morgan's rules and the existing spec; keep every other blocking behavior unchanged.

**Non-Goals:** changing what Morgan does, changing how Group Z is identified (the letter `Z` remains the convention), or treating non-Group-Z HUMAN items as non-blocking.

## Decisions

### D1: Identify checkpoints by group letter, not by tag
A pending item is ignored for dependency purposes when it sits in a group whose letter is `Z`, regardless of its `[HUMAN]` tag. Group Z is the roadmap convention for user-testing checkpoints and is what Morgan's rules name. Matching on the label text ("User Testing") would be brittle across projects.

### D2: Apply the exception only to dependency satisfaction
The exception affects only whether a *dependency* phase counts as satisfied. Group Z items in the phase being evaluated are untouched, `[HUMAN]` filtering elsewhere is untouched, and `status` counts are untouched.

### D3: Fail-closed rule from `nudge-gate-hardening` stays
An unresolvable dependency still blocks. The two rules compose: resolve the phase, then check its non-Group-Z items.

## Risks / Trade-offs

- [Idle continuation now fires on projects where it previously never did] → This is the intended behavior and already how Morgan behaves when running; the futile cap from `nudge-gate-hardening` bounds it.
- [`devshop action` lists more HUMAN items] → Correct per spec; the items were actionable all along.

## Migration Plan

Single PR; no data changes.
